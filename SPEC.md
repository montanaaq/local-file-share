# Техническое задание

## Общие требования

- Семестровая работа: собственный протокол обнаружения устройств, передачи файлов и текста поверх **UDP**.
- Равноправные приложения обмениваются данными напрямую в одной локальной сети, без сервера и регистрации.
- Файлы передаются как байты. При временном обрыве передача продолжается с первого недостающего чанка.
- Формат пакетов, сообщения и тайм-ауты: [PROTOCOL.md](PROTOCOL.md).
- Документ описывает целевое поведение; наличие требования не означает, что оно уже реализовано.

## Стек и структура

| Часть | Требование |
|-------|------------|
| Платформа | .NET 10, `net10.0`, C#, nullable, `async/await` |
| Сеть | `System.Net.Sockets.Socket`, UDP, broadcast; без `UdpClient` |
| Общая логика | Классовая библиотека `src/Protocol`, без точки входа и зависимости от Console, Avalonia и ViewModel |
| Клиент | `src/Client`, Avalonia 12.1.3, MVVM, CommunityToolkit.Mvvm 8.4.2 |
| Тесты | `tests/Protocol.Tests`, xUnit |
| ОС | Windows, macOS, Linux; разработка на macOS |
| CRC32 | Установленный `System.IO.Hashing` |

## Обмен

- При запуске создавать `deviceId` и сохранять до закрытия приложения. Это идентификатор экземпляра, а не доказательство подлинности.
- Слушать порт **5000** по умолчанию; менять порт до запуска обмена. Занятый порт — ошибка, совместное использование порта не включать.
- Строить локальный список устройств по `deviceId`; обновлять имя, адрес и доступность при обнаружении. Известные устройства и ручные адреса хранить до закрытия.
- Один цикл читает сокет. Ожидание ACK, решения пользователя, результата и SHA-256 не блокирует обработку других сообщений.
- `UdpTransport` отвечает за сокет, пакеты, seq, потери и ACK. Client использует общий код обнаружения, файлов и текста из Protocol.
- При закрытии завершать фоновые задачи и ожидания, освобождать сокет и файлы. Не скрывать неожиданные ошибки.

## Файлы

- Порядок: предложение → решение → чанки по одному → завершение → результат SHA-256. ACK, принятие файла и успешное сохранение — разные события.
- Получать данные в `.part`, хранить принятые чанки и `nextIndex`. Проверять метаданные, индекс и точную длину чанка. Пустой файл содержит 0 чанков.
- Перед сохранением проверить все чанки и SHA-256. Ошибка проверки — удалить `.part` и отправить отрицательный результат.
- Папка по умолчанию — «Загрузки». Очищать имя с учётом Windows на всех ОС; существующие файлы не перезаписывать, добавлять суффикс ` (1)`.
- Пауза сохраняет `.part` и прогресс. Возобновлять по паре `deviceId` отправителя и `fileId`, сверять метаданные и брать актуальный адрес устройства.
- При возобновлении отправлять FILE_OFFER с прежним `fileId` и новым `seq` каждые 2 с. Неудачная попытка не сбрасывает срок паузы. Каждая сторона отсчитывает 120 с от своего входа в паузу; затем ошибка и удаление `.part` у получателя.
- Известную принятую передачу возобновлять без нового решения пользователя, отвечая своим `nextIndex`. Неизвестный `fileId` считается новым предложением; при `nextIndex`, равном числу чанков, отправлять FILE_DONE.
- Результаты хранить по паре `deviceId` отправителя и `fileId` до закрытия. Для сохранённого файла повторять положительный FILE_ANSWER с полным числом чанков и прежний FILE_RESULT на FILE_DONE. После отрицательной проверки повторное предложение отклонять.
- Отмена в паузе локальная: удалить `.part`, сетевого сообщения отмены нет. Вторая сторона завершает ожидание по своему тайм-ауту.

## Клиент

Одно окно Avalonia; сетевые события переносить в поток UI на стороне клиента.

| Область | Содержимое |
|---------|------------|
| Настройки | Имя, локальный порт, переключатель обмена; по умолчанию обмен включён |
| Устройства | Имя, адрес, доступность, выбор получателя, ручное добавление `IP:порт` |
| Отправка | Выбор файла, drag & drop, отправка текста из буфера обмена |
| Входящий файл | Имя, размер, принятие или отказ |
| Передачи | Направление, имя, прогресс, состояние, число повторов |
| Пауза | Сохранённый прогресс, оставшееся время до ошибки, отмена |
| Принятый текст | Карточка с кнопкой копирования |
| Подробности | Отправки, ACK, повторы, потери, паузы и возобновления |

`LossRate` от **0 до 100%** действует на отправку и приём, включая поиск и ACK. Поле потерь и переключатель «Обрыв связи» устанавливают 100% и восстанавливают предыдущее значение. Сетка чанков необязательна.

Отключение обмена останавливает сетевые операции и переводит незавершённые передачи в паузу. Таймер паузы продолжает действовать.
Начатая проверка SHA-256 и сохранение уже полученного файла завершаются локально; результат сохраняется для передачи после включения обмена.

## Проверка

```sh
rtk proxy dotnet build LocalFileShare.slnx
rtk proxy dotnet test tests/Protocol.Tests/Protocol.Tests.csproj
rtk proxy dotnet run --project src/Client/Client.csproj
```

Protocol отдельно не запускается. Интеграционные тесты создают несколько PeerService и проверяют прямой UDP-обмен. Команда запуска Client открывает Avalonia; сетевые функции UI пока не подключены. Сценарии ниже задают критерии приёмки готового клиента.

| Сценарий | Ожидаемый результат |
|----------|---------------------|
| Два локальных экземпляра, порты 5000 и 5001, файл около 5 МБ | Обнаружение, прямой обмен, совпадение SHA-256, файл открывается |
| Потери 20–30% | Целый файл, повторы больше нуля |
| Отказ | Отправитель видит отклонение |
| LossRate 100% у каждой стороны по отдельности, через 15 с 0% | Пауза и продолжение с первого недостающего чанка без перезапуска |
| Обрыв дольше 120 с | Ошибка; работающий получатель удаляет `.part` |
| Текст | Доставка и копирование на втором устройстве |
| macOS и Windows в LAN, порт 5000 | Автоматическое обнаружение и передача без ручного адреса |
| Закрытие второго приложения | Исчезновение из списка онлайн не позднее 5 с |
| Отключение Wi-Fi на 10–20 с | Пауза и возобновление без ручного переподключения |

Тесты должны проверять полный обмен и SHA-256, отказ, дубликаты, некорректный чанк, возобновление и очистку `.part` после тайм-аута. Отдельно указывать автоматические проверки, проверку двумя процессами и проверку на разных ОС в LAN.

Вне объёма: TCP поверх UDP, скользящее окно, контроль перегрузки, шифрование, аутентификация, NAT traversal, интернет, мобильные ОС, папки, поиск за пределами подсети и возобновление после перезапуска.
